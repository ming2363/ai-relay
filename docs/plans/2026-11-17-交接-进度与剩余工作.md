## 一、项目和用户要求速览

ai-relay 是 Claude Code 插件，由两部分组成：

- `plugins/ai-relay`：脚本和钩子。主模型 Claude 当"主管"，通过 `relay.mjs` 把子任务派给其他模型（"员工"）的命令行工具。
- `plugins/ai-relay-status`：面板，有额度、对话、厂商三页。

用户的目标：

1. 把各家 AI 会员额度用足。
2. 交付质量保持在 Claude 的水平。

用户定的硬规矩：

| 规矩 | 具体要求 |
|---|---|
| 复核铁令 | 每个员工交回的结果，主管都要亲自复核：看 diff、自己跑测试、回源码核对结论。发现问题自己负责改到对：退回返工、改派或自己补，**不要把问题丢给用户** |
| git | "提交 git"指 commit 加 push，只在用户当轮明确要求时做，推送后核对远端。员工不得做任何 git 写操作 |
| 密钥 | 密钥的值不得出现在任何文件、命令行参数、日志、汇报里 |
| 语言 | 注释、提示文字、文档、提交信息用中文 |
| 方案设计 | 不靠"注明""加个说明"兜底，方案本身要成立 |

### 2. 脚本端接线（B4、B6 依赖这些，现在面板上的统计和归池下拉调用的命令还不存在）

在 `plugins/ai-relay/scripts/relay.mjs` 里做三件事：

1. **新命令 `relay stats [--days N] [--json]`**：
   - 读全部任务记录（`lib.mjs` 的 `allJobRecords()`）和 `~/.claude/ai-relay/rounds/*.json` 的全部轮次。
   - 调 `stats.mjs` 的 `workStats`。
   - `--json` 输出它的返回值，否则输出中文摘要。
   - 在 `help()` 里加说明。
2. **额度周期采样**：
   - `cmdStatus` 里读完额度行后，调 `sampleQuotaHistory(STATE_DIR, rows)`。面板每次刷新都会调 `status --json`，采样就靠它。
   - `status --json` 的每个额度池加 `lastCycles` 数组，内容取 `lastCycles(STATE_DIR)` 里该"厂商|池"下的各窗口，每项形如 `{ window, leftover, endedAt, reliable }`。
   - 注意：额度行里的 `provider` 是额度来源名（如 agy 的是 `prov.quota.provider`），不是厂商名，对应时要用厂商的 `quota.provider`。
3. **新命令 `relay provider pool-rule <厂商> <模型名关键字> <额度池>`**：
   - 往该厂商的 `poolRules` 最前面插一条 `[关键字, 池]`（已有相同关键字的就替换）。
   - 额度池必须是该厂商已有的池。
   - 写回配置后，把模型清单缓存里匹配的模型重新归池（或者直接让下次 `relay models` 刷新）。
   - 在 `cmdProvider` 的分发和 `help()` 里加上。

每一项都要有测试（临时 HOME）。做完后在真实面板里确认三处显示：工作量卡、上个周期剩余、未归池下拉。

## 六、踩过的坑

| 坑 | 对策 |
|---|---|
| 派单太大会跑满时长上限、没有产出 | 一张派单控制在一个模块、几个函数，加 `--max-runtime 90` |
| 员工常犯：删掉看似无用的分支（删过"缓存过期自动刷新"和"直接停在厂商页时加载模型清单"），以及自己放宽旧测试断言 | 复核时专看删除行 |
| 测试数据和真实数据格式不一致（统计函数把任务时间当数字，真实是 ISO 字符串，测试全过但真实结果全错） | 能用本机真实数据跑一次就跑一次 |
| 并行任务改同一个文件会互相覆盖 | 每张派单写清「写入范围」，范围不重叠才并行。验收报告里"越界"提示常是并行任务互相改文件造成的误报，要核对是谁改的 |
| `relay self "<原因>"` 被钩子漏识别 | 输出不要接 `\| tail`，钩子靠输出里的 `[relay-self]` 行识别 |
| 通过标准输入写密钥时，用管道 relay 可能读不到内容 | 先写进权限 600 的临时文件，用 `< 文件` 重定向，用完删掉 |
| `--steps` 被退回 | 每一步都必须写到具体文件路径，否则会被退回 |
