## 二、剩余工作（按顺序）

### 1. 修复：后台员工写的行数被算到主管名下

- **现象**：主管用 Bash 时，钩子在命令前后各拍一次 git 快照，用差值计"亲手写的行数"（`lib.mjs` 的 `lineSnapshot` / `handwrittenDelta`，`posttool-hook.mjs` 的 `handlePostBash`）。如果此时有 `relay run --write --background` 的员工在同一仓库写文件，员工写的行也被计入。实测一次显示 250 行，主管实际只改了几行。这会误触发"自己做超过 40 行要求重新定分工"的拦截。
- **改法**：
  - 计算 Bash 差值时，排除"正在运行的可写外派任务"的写入范围内的文件。运行中的任务可从 `relay.mjs` 的 `runningWriters()` 或 jobs 目录里 `status: "running"` 且 `write: true` 的任务取得，用它们的 `scope` 和 `cwd`。
  - 没写 scope 的运行中可写任务：该仓库这次 Bash 计 0。
- **验收**：
  - 测试：有运行中的可写任务、其范围内文件在主管 Bash 期间变化时不计入；范围外的照常计入。
  - 原有测试全过。

### 2. 修复：Grok 额度显示和实际不一致

- **现象**：面板显示 Grok 周额度 100%，但它的命令行报 `You've reached your free Grok Build usage limit`，任务中途失败。
- **改法**：
  - 在 `relay.mjs` 的 `executeJob` 结束处，输出里出现"usage limit / reached your … limit / rate limit / quota exceeded"类文字时，标记 `job.quotaExhausted = true`。
  - 同时把该额度池在 `quota-cache.json` 里记为剩余 0，重置时间未知时设为 24 小时后，这样选人会跳过它。
  - 面板该池显示"命令行报额度用完"。
- **验收**：测试用假输出覆盖。用户重新启用 Grok 前先验证。

## 四、这几轮踩过的坑

- **派单要小**：一张派单控制在一个模块、几个函数。上一次把整个批次 2 派给一个员工，跑满 4 小时没有任何产出。派单时加 `--max-runtime 90`。
- **员工常犯的两类错**：
  - 删掉看似无用的分支，导致倒退。例如删了"缓存过期自动刷新"、删了"直接停在厂商页时加载模型清单"。
  - 不按派单改了旧测试的断言。
  - 复核时专门看 diff 里的删除行（`-` 开头）。
- **登记"自己做"时不要截断输出**：`relay self` 的输出要完整，不要接 `| tail`。钩子靠输出里的 `[relay-self]` 行识别登记。
- **密钥通过标准输入写入时，用文件重定向**：用 `< 文件`，不要用管道，否则 relay 可能先于写入端读完标准输入。
- **"提交 git"指 commit 加 push**，只在用户当轮明确要求时做，推送后核对远端。员工不得做任何 git 写操作。
