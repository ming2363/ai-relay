## 三、批次 1：接入自定义接口，并给密钥打码

目标版本：ai-relay 0.22.0，面板 0.26.0。

### 已探明的事实（2026-11-11）

- 接口地址 `https://model-api.maas.com.cn`，是 new-api 类型的网关，按量计费。
- `GET /v1/models` 返回 24 个模型。OpenAI 对话（`/v1/chat/completions`）、OpenAI Responses（`/v1/responses`）、Anthropic Messages（`/v1/messages`）三种协议都能返回，工具调用也能返回。
- 余额接口可读：`GET /v1/dashboard/billing/subscription` 和 `/v1/dashboard/billing/usage`，金额单位未确认。
- **只读试跑已通过**：下面这条命令用 `qwen3.8-max` 和 `deepseek-v4-pro-0813` 都能读文件并正确回答（各 2 轮，7 到 12 秒）。

  ```bash
  ANTHROPIC_BASE_URL=https://model-api.maas.com.cn ANTHROPIC_API_KEY=<密钥> \
    claude --bare -p "<任务>" --model qwen3.8-max --output-format json --permission-mode plan
  ```

  注意地址不带 `/v1`，Claude Code 会自己拼 `/v1/messages`。标准错误里会有一行 `[claude-code:unrecognized_model]`，不影响结果。
- **可写试跑没做**：方案作者所在的会话不允许启动带 `--dangerously-skip-permissions` 的子进程。执行方第一步要补这个试跑（见本节"验收"第 1 条）；如果执行方的环境也被拦，把命令交给用户在终端里跑。
- 本机已装 Claude Code 2.1.318 和 codex-cli 0.166.0；没装 opencode。Codex 0.166 的自定义厂商只支持 Responses 协议，这里不用它当外壳。

### 设计

**外壳用 Claude Code 命令行的精简模式。** `--bare` 会跳过钩子、插件、CLAUDE.md 自动发现，也不读取登录凭据，认证只认 `ANTHROPIC_API_KEY`。所以子进程不会加载 ai-relay 的钩子（不会套娃），也不消耗用户的 Claude 会员额度。项目规则由 relay 的派单包附带，不依赖 CLAUDE.md 自动发现。

**厂商配置新增一种类型。** 在 `providers.json` 的厂商对象里加这些字段（现有 CLI 厂商不受影响）：

```json
"maas": {
  "label": "国产模型（自定义接口）",
  "via": "relay",
  "billing": "metered",
  "endpoint": { "baseUrl": "https://model-api.maas.com.cn", "secret": "maas" },
  "cli": {
    "bin": "claude",
    "prompt": ["--bare", "-p", "{prompt}", "--output-format", "json"],
    "model": ["--model", "{model}"],
    "read": ["--permission-mode", "plan"],
    "write": ["--permission-mode", "acceptEdits"],
    "cwd": null,
    "fullAccess": ["--dangerously-skip-permissions"],
    "fullAccessWriteOnly": true
  },
  "env": {
    "ANTHROPIC_BASE_URL": "{baseUrl}",
    "ANTHROPIC_API_KEY": "{secret}",
    "ANTHROPIC_SMALL_FAST_MODEL": "deepseek-v4.1-flash-1017",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
    "DISABLE_TELEMETRY": "1"
  },
  "envUnset": ["ANTHROPIC_AUTH_TOKEN", "CLAUDECODE", "CLAUDE_CODE_ENTRYPOINT"],
  "pools": { "maas": ["deepseek-v4-pro-0813", "deepseek-v4.1-flash-1017", "glm-5.3", "qwen3.8-max", "kimi-k3.1-pro", "doubao-seed-2-0-pro-260215", "MiniMax-M2.5"] },
  "defaultModels": { "maas": "qwen3.8-max" },
  "caps": { "web": false, "exec": false, "vision": false },
  "modelCaps": {
    "qwen3.8-max": { "vision": true },
    "kimi-k3.1-pro": { "vision": true },
    "doubao-seed-2-0-pro-260215": { "vision": true },
    "deepseek-v4.1-flash-1017": { "vision": true }
  },
  "modelList": { "format": "openai-http" }
}
```

要点：

- `pools` 里列出的就是白名单，只接这 7 个。用户点名的是 DeepSeek 两个、GLM 5.3、千问 3.8 Max；Kimi、豆包、MiniMax 是按"每家最旗舰的一个"补的，用户可能会删。`c-opus-*`、`g-5.6-sol`（不是国产）、各家 flash 和 lite（DeepSeek flash 除外）、`kimi-k3`、`ZHIPU/GLM-5.3`（与 `glm-5.3` 同模型不同通道）、向量、重排、语音、图像模型都不接。
- `fullAccessWriteOnly`：只读任务永远只带 `--permission-mode plan`，不追加 `fullAccess` 参数；可写任务在最高权限开关打开时用 `fullAccess` 的参数**替换** `write` 的参数。现在 `buildCommand`（`relay.mjs:214-231`）对所有任务都追加 `fullAccess`，要按这个字段分支。
- `caps.exec` 的实际取值沿用现有"最高权限开关打开就算能执行命令"的机制。
- `--output-format json`：relay 取其中的 `result` 作为任务输出，`usage` 里的输入输出 token 记进任务（供面板显示和每日上限用）；输出不是合法 JSON 时原样当文本。标准错误只进日志。

**环境变量。** 现在 `executeJob` 的 `spawn`（`relay.mjs:317-321`）不传 `env`，直接继承。改为：厂商有 `env` 或 `envUnset` 时，在继承的基础上覆盖和删除；`{baseUrl}` 取 `endpoint.baseUrl`，`{secret}` 取密钥文件里 `endpoint.secret` 对应的值。密钥文件里没有这个名字时，任务直接失败并提示用户运行设置密钥的命令。

**密钥存放。**

- 文件 `~/.claude/ai-relay/secrets.json`，内容 `{ "<名字>": "<密钥>" }`，权限 600，写入时先设权限再写内容。
- 新命令 `relay provider key <厂商名>`：从终端读取，不回显；也支持从标准输入读（`--stdin`）。**不接受命令行参数形式的密钥**（会进 shell 历史和进程列表）。`relay provider key <厂商名> --clear` 删除。
- `relay providers --json` 只输出 `hasKey: true|false`。
- 写任务日志和任务结果前，把出现的密钥原值替换成 `***`（员工可能把环境变量打印出来）。
- 用户已经在聊天里贴过一次密钥，它留在 Claude Code 自己的会话记录里，插件清不掉。接好后提醒用户换一个新密钥，并用上面的命令输入。

**计费和派单顺序。** 厂商带 `"billing": "metered"` 表示按量计费：

- 自动选人时"会员优先、按量兜底"：候选里只要有会员额度池的合格候选，按量的就排在它们后面；会员候选全部不可用时才选按量的。点名（`relay run maas --model …`）随时可用。
- 没有额度数据，`poolStatus` 返回 `unknown`，面板和 `relay status` 显示"按量计费"，不显示百分比。
- 每日上限：新配置 `meteredDailyTokenCap`，默认 2000 万 token。relay 按天累计按量厂商的输入加输出 token（存 `~/.claude/ai-relay/metered-usage.json`），超过后自动选人跳过按量厂商，原因写"今日按量用量已到上限"；点名仍可用。
- 余额显示先不做：金额单位没确认，确认后再加。

**档位和路由。**

- `modelTiers` 增加：`maas:deepseek-v4.1-flash-1017` 为轻档，其余 6 个为中档。都不进强档：它们的实际水平没有依据，困难任务仍只派会员里的强档，之后靠验收结论形成的可靠度分和用户在面板里的调整来校正。
- 路由追加在各角色现有条目之后：

  | 角色 | 追加的条目（擅长度） |
  |---|---|
  | implement、review | 6 个中档各 0.75，flash 0.5 |
  | debug、deep | 6 个中档各 0.65 |
  | read | flash 0.8，6 个中档各 0.7 |
  | quick | flash 0.8 |

  配置迁移要写成幂等的：已有用户的 `providers.json` 不自动加这个厂商，只有用户通过面板或 `relay provider add` 添加后才写入厂商、档位和路由。

**模板和面板。**

- `plugins/ai-relay/config/presets.json` 加 `endpoint` 模板（标题"自定义接口"），字段是名称、接口地址、模型白名单。现有的 `custom` 模板是给"有官方命令行的厂商"用的，保留不动。
- `relay provider add` 支持这个模板（`relay.mjs:1037-1075`）。
- `models.mjs` 的 `parseByFormat`（`models.mjs:182-187`）加 `openai-http`：用密钥请求 `{baseUrl}/v1/models`，解析 `data[].id`。
- 面板 `PRESET_ORDER`（`register.tsx:93`）加 `endpoint`；厂商页表单（`register.tsx:2988-2995` 附近）在选这个模板时显示名称和接口地址两个输入框，保存后显示"密钥：已设置 / 未设置"和设置密钥要运行的命令。面板不提供密钥输入框。接口上不在白名单里的模型列出来标"未启用"，可勾选加入。

### 多模态（看图）能力

用户要求：弄清每个员工能不能看图，派单时据此选人。现在能力标记只有联网和执行命令两项（`capsOf`，`lib.mjs:1615-1618`），不区分能不能看图，带截图的任务可能被派给看不了图的模型。

**实测结果（2026-11-11，测试图是左蓝右黄、中间一条黑线）：**

| 员工 | 能看图 | 怎么测的 |
|---|---|---|
| agy · Gemini 3.8 Flash | 能 | 走真实派单，让它读图片文件；答对颜色，并说出了派单没提的黑线 |
| Grok 4.7 | 能 | 同上 |
| 自定义接口 · qwen3.8-max | 能 | 直接调接口发图片 |
| 自定义接口 · kimi-k3.1-pro | 能 | 同上 |
| 自定义接口 · doubao-seed-2-0-pro | 能 | 同上 |
| 自定义接口 · deepseek-v4.1-flash | 能 | 同上 |
| 自定义接口 · deepseek-v4-pro | 不能 | 回答"看不到"，而且这次请求用了 162 秒 |
| 自定义接口 · MiniMax-M2.5 | 不能 | 回答"看不到" |
| 自定义接口 · glm-5.3 | 不能 | 接口直接报错：模型只支持文本输入 |
| Codex | 未测 | 周额度不足，派不出去 |

自定义接口的 4 个"能"是直接调接口测的，还没有经过 Claude Code 外壳读图片文件这条路，执行方要补测一次。

**设计：**

- 能力标记加一项 `vision`。厂商级写在 `caps.vision`；同一厂商里各模型不一样时，用新字段 `modelCaps.<模型>.vision` 覆盖。`capsOf` 增加模型参数，按"模型覆盖优先、否则取厂商级"返回。
- 默认值（`providers.default.json` 和迁移）：agy 和 Grok 厂商级为 `true`；Codex 为 `false`，等额度恢复后实测再改；自定义接口厂商级 `false`，上面 4 个模型单独设 `true`。未实测的 agy 其他模型先跟随厂商级，执行方在额度恢复后各补测一次，不能看图的写进 `modelCaps`。
- 派单「## 需要的能力」认"看图"：`needsOfBrief`（`brief.mjs:168-196`）在正文出现"看图、图片、截图、图像、多模态"时加 `vision`。
- 不依赖主管记得写：`brief.mjs` 加一个检查，派单任何位置出现图片文件路径（`.png .jpg .jpeg .gif .webp .bmp`）时自动把 `vision` 加进需要的能力。
- 选人筛选：`capsSkipWhy`（`score.mjs:301-310`）加"看图"，不具备的候选跳过并写"不具备：看图"；这里要按候选的具体模型取能力，不能只按厂商。`relay pick --needs` 支持 `vision`。点名一个看不了图的模型去做带图任务时，`relay run` 退回。
- Codex 子代理钩子里的能力检查（`pretool-hook.mjs:157-163`）加同样的判断。
- 给看不了图的模型的派单包里自动加一条规则："你看不了图片，不要用读文件工具打开图片文件；需要图片内容时在汇报的『需要主控协助』里写明"。原因：实测 glm-5.3 收到图片会让整次请求报错，任务会直接失败。

- 面板厂商页每个模型旁显示能不能看图；`relay providers` 的输出带上。SKILL.md 第一点五节的能力表加"看图"一列，并补一句带图任务的派法。`BRIEF_TEMPLATE` 的「需要的能力」说明加"看图"。

### 验收

1. 可写试跑：在临时目录放一个有错的小函数和一个检查脚本，用 `deepseek-v4-pro-0813` 走 `relay run maas --write`，员工能改对文件并自己运行检查脚本。再用 7 个模型各跑一次只读小任务，跑不通的从白名单里去掉并在汇报里列出。
2. 只读任务的命令行里没有 `--dangerously-skip-permissions`；可写任务在最高权限关闭时用 `acceptEdits`。
3. 子进程的环境里有接口地址和密钥，没有 `ANTHROPIC_AUTH_TOKEN`、`CLAUDECODE`；`ps` 看到的命令行里没有密钥。
4. `secrets.json` 权限是 600；`providers.json`、任务 json、日志、`relay providers --json` 里搜不到密钥原值；员工输出里故意打印密钥时，日志里是 `***`。
5. 会员候选可用时 `relay pick implement --level 中等` 的首选不是 maas；把会员候选都设成不可用后首选是 maas；到每日上限后自动选人跳过它，点名仍能跑。
6. 含 `sk-` 长串的用户消息，存进 `prompts/` 和 `rounds/` 后都是打码的；已有文件在下一次每日清理后也被打码。
7. 看图：派单里写了图片路径但没写需要的能力时，`relay pick` 仍会跳过看不了图的模型并写明"不具备：看图"；点名 `glm-5.3` 做带图任务被退回；派给它的不带图任务，派单包里有"不要打开图片文件"那条规则。用 `qwen3.8-max` 走 `relay run maas` 读一张图片文件并答对内容。
8. 新增单元测试覆盖第 2 到 7 条（第 7 条最后一句是实跑，不算单元测试）；原有测试全过。

## 四、批次 2：按重置时间配速 + 中等任务先派中档

目标版本：ai-relay 0.23.0。只改打分和节流档位，不新增拦截。

### 现状

- 总分是五项的加权几何平均，`calcWeightedScore`（`score.mjs:252-266`）；默认权重 `fit 3 / reliability 3 / quota 0.25 / speed 0.5 / load 0.5`（`score.mjs:14-23`）。额度权重最低是用户明确定过的，不改。
- 额度项 `calcQuota`（`score.mjs:143-163`）：`0.6 + 0.4×剩余 + 0.4×快到期的剩余`，低于 30% 再乘 0.7。
- 低于 15% 直接跳过（`score.mjs:386-397`，阈值 `minRemaining`）。这条保留。
- `LEVEL_RULES`（`score.mjs:54-58`）：中等任务是"中档以上按综合分"，强档因为擅长度高经常胜出。
- Claude 节流 `claudeThrottle`（`lib.mjs:297` 起）：剩余低于 50% 为 1 档，低于 20% 为 2 档，不看离重置还有多久。
- 额度窗口数据里有 `remaining`、`resetAt`、`key`（`5h` 或 `weekly`）；窗口总时长由 `windowTotalHours(key)`（`score.mjs:109`）得出。

### 设计

**配速值。** 对每个有剩余比例和重置时间的窗口：

```
周期剩余比例 = clamp(距重置小时数 / 窗口总小时数, 0, 1)
配速 = 额度剩余比例 − 周期剩余比例
```

正数表示用得比进度慢（有富余），负数表示用得比进度快。一个额度池的配速取各窗口里的最小值。没有重置时间的窗口不参与；一个都算不出时配速为"未知"，行为与现在相同。把这个计算放进 `lib.mjs`（`score.mjs` 已经从它导入），`windowTotalHours` 一并移过去。

**用在三处：**

1. 额度项改为 `clamp(0.8 + 0.6×配速, 0.5, 1.4)`；配速未知时保持现在的公式。配速不为负时，不再因为"低于 30%"打七折。
2. 保留规则：配速低于 `paceReserveBelow`（默认 −0.15）的额度池，简单和中等任务把它排到所有其他候选之后，理由写"用得比进度快，留给困难任务"；困难任务不受影响。它不是跳过：别的候选都不可用时仍然会选到它。
3. 近似同分时让富余的先上：候选分数与最高分相差不超过 `paceTieBand`（默认 5%）的，按配速从高到低排。这样不动用户定的权重，只在质量相当的候选之间调顺序。

**中等任务先派中档。** `LEVEL_RULES.medium` 加 `preferTier: "mid"`。中等任务的候选排序依次是：

1. 会员额度池的中档；
2. 会员额度池的强档（没进保留的）；
3. 按量计费的中档；
4. 进了保留的额度池。

每一组内部按分数排（含上面第 3 条的近似同分规则）。被排后的候选在 `relay pick` 的输出里写明原因。简单任务的顺序是：会员、按量、保留。困难任务不变。

**Claude 自己的节流也按配速。** `claudeThrottle` 改为：

- 0 档：配速不低于 `claudePaceThrottle`（默认 −0.10）；
- 1 档：配速在 −0.30 到 −0.10 之间；
- 2 档：配速低于 `claudePaceConserve`（默认 −0.30），或者剩余低于 `claudeConserveBelow`（现有，0.2）。
- 配速未知时退回现在按 50% 和 20% 判断的逻辑。

注入的节流提示（`prompt-hook.mjs:40-54`）里把"只剩 X%"改成"剩 X%，周期还剩 Y%"。

### 验收

1. 单元测试：剩 90%、周期剩 30% 的额度池额度项高于剩 30%、周期剩 90% 的；后者在中等任务里排到最后，在困难任务里位置不变。
2. 两个候选分数相差 3% 时配速高的排前面；相差 10% 时仍按分数。
3. 中等任务：会员中档和会员强档都可用时首选是中档；中档全部不可用时首选是强档。
4. Claude 剩 40%、周期剩 15% 时是 0 档；剩 40%、周期剩 80% 时是 2 档；没有重置时间时与旧逻辑一致。
5. `relay status` 和 `relay pick` 的输出里能看到配速和被排后的原因；原有测试里与旧公式绑定的断言按新规则改，并在汇报里列出改了哪些。

## 五、批次 3：步骤规格降档 + 自动验证和初审

目标版本：ai-relay 0.24.0。

### 步骤规格降档

用途：中档没人可用时，主管把任务写成步骤级的规格，交给轻档照着做，而不是自己做。

- `brief.mjs` 加 `stepsOfBrief(text)`，仿照 `needsOfBrief`（`brief.mjs:168-196`）解析「## 步骤」小节。合格的步骤规格：至少 2 步，每一步都点到具体文件路径。
- 派单难度为中等且带合格的步骤规格时，轻档模型可以接（门槛降一档，逻辑接在 `tierAllowed`，`score.mjs:66-70`），分派理由里写"带步骤规格，轻档可接"。困难任务不适用。没有步骤规格时行为不变。
- `relay pick --level 中等 --steps` 可以预览带规格时的候选。中等任务没有任何候选时，`relay pick` 的输出加一段：列出轻档候选，并说明把任务写成步骤规格后可以派给它们。
- Codex 子代理钩子里的档位检查（`pretool-hook.mjs:116-231`）用同一条规则。
- `BRIEF_TEMPLATE` 和 SKILL.md 加这一小节的说明。

### 自动验证

- `brief.mjs` 加 `verifyOfBrief(text)`，解析「## 验证命令」小节：每个非空行一条命令，最多 3 条。
- `executeJob` 在任务结束、算完 `changedFiles` 之后（`relay.mjs:445-453`）：任务可写且派单带验证命令时，在任务目录里依次用 `sh -c` 执行，每条默认超时 10 分钟（配置 `verifyTimeoutMin`），记录退出码、耗时和输出的最后 40 行到 `job.verify`。
- `relay result` 和 `relay wait` 的输出加一段"自动验证：通过 / 未通过"和输出尾部。未通过不改变任务状态，只加 `verifyFailed` 标记，并提示可以用 `relay rework` 退回。
- 同时记录改动行数 `job.changedLines`：任务开始和结束各拍一次 `lineSnapshot`，用 `snapshotDelta` 求差（`lib.mjs` 里已有，Bash 行数统计在用）。现在任务只记了改动文件列表，没有行数。
- 派给 Codex 子代理的任务不在这次范围内。

### 自动初审

- 条件：任务可写、正常结束、`changedLines` 不少于 `autoReviewMinLines`（默认 150）、任务本身不是 review、配置 `autoReview` 不为 `false`（默认开）。
- 动作：自动在后台起一个只读的 review 任务，难度中等，按现有打分选人但排除实现者所在的厂商（给选人函数加"排除厂商"的参数），附上当前 diff 和原任务的结果。派单的目标和验收标准从原派单生成，并附原派单全文。
- 原任务记 `autoReviewId`；`relay wait` 在原任务结束时就返回，不等初审，输出里给出初审任务的 id。
- 没有可用的审查员工时不做初审，在原任务结果里写"没有可用的审查员工，未做初审"。
- 主管的复核不变：实现任务和初审任务都要看过、各记一次验收结论。SKILL.md 第五节相应补充。

### 验收

1. 中等任务、中档全不可用：不带步骤规格时 `relay run` 轻档被退回；带合格规格时放行；规格只有 1 步或步骤里没有文件路径时仍退回。
2. 带验证命令的可写任务结束后，`job.verify` 有每条命令的退出码和输出尾部；验证命令失败时有 `verifyFailed`，任务状态不变；超时会被终止并记为失败。
3. 改 200 行的可写任务结束后自动起了另一家厂商的 review 任务；改 50 行的不起；`autoReview: false` 时不起；只有实现者一家可用时不起并写明。
4. `relay wait` 不因初审而延迟返回。
5. 以上都有单元测试；原有测试全过。
